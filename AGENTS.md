# AGENTS.md — Инструкции для AI-агентов проекта win_search

## Правила релизов и выпуска патчей

При пересборке поиска, изменении ранжирования или выпуске любых исправлений и патчей:
1. **Инкремент версии:** поднять версию приложения (patch/minor) синхронно во всех конфигурационных и сборочных файлах:
   - `release-version.json` (`version`)
   - `port/WAI-5c5c1f3ae2b4346353e34704b4783956d1ae8c4f/windows/src/WAI.App/AppConstants.cs` (`Version`)
   - `port/WAI-5c5c1f3ae2b4346353e34704b4783956d1ae8c4f/windows/Directory.Build.props` (`Version`, `FileVersion`, `AssemblyVersion`)
   - `port/WAI-5c5c1f3ae2b4346353e34704b4783956d1ae8c4f/windows/scripts/build-package.ps1` (`$Version`)
   - `scripts/publish-release.ps1` (`$Version`)
   - `port/WAI-5c5c1f3ae2b4346353e34704b4783956d1ae8c4f/windows/docs/Builder-Guide.md` и `User-Guide.md`
2. **Обновление документации:**
   - **`README.md`**: обновить номер версии, бейджи, ссылки на скачивание (Setup.exe, Portable.zip), блок ключевых возможностей текущей версии и пути в примерах вызова CLI.
   - **`CHANGELOG.md`**: добавить раздел с описанием исправлений и улучшений.
   - **`BACKLOG.md`**: дополнить список выпущенных релизов.
   - **`docs/RELEASE_<version>.md`**: создать подробные заметки о релизе.
3. **Публикация в GitHub:**
   - Закоммитить изменения с информативным сообщением (`fix(...)` / `chore(...)`).
   - Создать аннотированный Git-тег (`git tag v<version>`).
   - Опубликовать изменения в удалённый репозиторий: `git push origin main && git push origin v<version>`.

## Правила поиска и ранжирования
- Точные совпадения имён файлов и основы имени должны иметь приоритет над семантическими векторными совпадениями.
- Расширения файлов (`.jpg`, `.png`, `.docx` и др.) и слова категорий не должны размывать полнотекстовый поиск.
- Проценты релевантности в интерфейсе нормализуются относительно максимального балла выдачи.
