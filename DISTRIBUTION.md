# Установка, сборка и распространение WAI для Windows

Здесь описан публичный пакет, чистая сборка WAI 1.2.4 и порядок выпуска. Источник точных версий, адресов, размеров и SHA-256 нативных архивов — [`native-dependencies.json`](native-dependencies.json); скрипт подготовки сверяет архивы перед распаковкой.

## Публичная версия

Пакет [WAI 1.2.4](https://github.com/ex-ru/win_search/releases/tag/v1.2.4) содержит per-user установщик и portable-архив. Описание изменений — в [заметках к релизу 1.2.4](docs/RELEASE_1.2.4.md); базовый состав проверок и контрольные суммы описаны в [отчёте выпуска 1.2.1](docs/RELEASE_VERIFICATION_1.2.1.md).

Используйте [последний релиз](https://github.com/ex-ru/win_search/releases/latest) или команды:

~~~powershell
.\scripts\download-release.ps1
.\scripts\download-release.ps1 -Portable
~~~

Первый вариант скачивает per-user установщик, второй — portable-архив; оба проверяют SHA-256. Сборки не подписаны: перед запуском проверьте источник и файл `SHA256SUMS.txt` на странице релиза.

## Чистая сборка 1.2.4

Сборка рассчитана на Windows x64 с PowerShell 5.1 или 7, Git и .NET SDK **10.0.402**. Версия зафиксирована в `global.json` без автоматического перехода на другой SDK. Сборка использует NuGet lock-файлы проектов в режиме locked restore и закреплённый Velopack CLI 1.2.161; Python, CUDA и Visual Studio C++ для стандартной упаковки не нужны.

Из корня checkout проверьте SDK, выполните тесты в locked mode, затем соберите полный пакет:

~~~powershell
dotnet --version
$win = '.\port\WAI-5c5c1f3ae2b4346353e34704b4783956d1ae8c4f\windows'
dotnet test "$win\WAI.Windows.sln" -c Release -p:RestoreLockedMode=true --logger trx
.\scripts\build-release.ps1
~~~

Обёртка читает версию из `release-version.json`; для 1.2.4 результат размещается в `dist\1.2.4\staging` и `dist\1.2.4\releases`. Стандартная сборка всегда включает FFmpeg; прежний профиль Slim больше не поддерживается. `scripts\prepare-runtime.ps1` получает закреплённые архивы llama.cpp b11461, PDFium 157.0.8100.0 и FFmpeg 9.0.2 вместе с соответствующим source bundle, проверяет SHA-256, собирает перечень хешей runtime и копирует обязательные notices. Managed зависимости восстанавливаются по `packages.lock.json`; пропущенные или неразрешённые уведомления блокируют упаковку.

На первом выпускном прогоне архивы FFmpeg ещё не доступны по URL будущего релиза. CI workflow `.github/workflows/package.yml` получает их как артефакт из Actions run, указанного полем `ffmpegBuildRun` в `release-version.json`, и передаёт builder-у. При локальной сборке до публикации положите `ffmpeg-tools-win-x64.zip` и `ffmpeg-corresponding-source.zip` из того же run в `tools\native-cache`; их размеры и SHA-256 должны совпадать с `native-dependencies.json`. После публикации релиза недостающие архивы скачиваются с закреплённых URL автоматически. Не заменяйте их произвольными локальными FFmpeg/PDFium/llama файлами.

`native-dependencies.json` также закрепляет исходные архивы FFmpeg 9.0.2, dav1d 1.5.4 и zlib 1.3.2. В комплекте релиза лежат `native-provenance.json`, полный набор сторонних уведомлений и `ffmpeg-corresponding-source.zip` с исходниками и рецептом сборки. Подробности о лицензиях — в [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md). Модели в приложение не встраиваются: при первом запуске выбранная модель загружается и проверяется по размеру и SHA-256 из каталога моделей.

Зафиксированные SDK, NuGet, native-архивы и Velopack позволяют повторить сборку из проверенных входов; это не обещание побайтного совпадения всех Velopack-артефактов между разными машинами и запусками.

## Проверки перед публикацией

Запускаемый вручную workflow выполняет locked restore и тесты, собирает полный self-contained пакет, проверяет его нативные файлы/уведомления и загружает артефакты только в черновик GitHub Release. Этот CI шаг сам по себе не завершает выпуск.

До перевода черновика в публичный релиз отдельно проверяются собранный `staging` с реальной закреплённой моделью, поиск по тестовой коллекции, PDF/медиа декодирование, повреждённая загрузка и применение portable-обновления с версии 1.2.0. Для последней проверки нужны оригинальные release assets 1.2.0; исторические файлы и их SHA-256 нельзя подменять пересобранным кандидатом. Команды и результаты фиксируются в [`RELEASE_VERIFICATION_1.2.1.md`](docs/RELEASE_VERIFICATION_1.2.1.md). Результаты относятся к загруженным из CI файлам релиза; их контрольные суммы позволяют связать проверки с конкретным пакетом.

После успешных gates `scripts\publish-release.ps1` сверяет SHA-256 и размер набора файлов, создаёт неизменяемый тег и публикует релиз. Передавайте ему полный SHA именно проверенного коммита. Интерактивная установка и обновление GUI на чистой Windows 11 остаются отдельным внешним тестом владельца и его добровольцев; автоматические проверки его не заменяют и он не отмечается пройденным до получения результата.

## Обновления и данные

Пакет использует идентификатор `WinSearch.WAI`. Данные WAI в `%LocalAppData%\WAI` сохраняются. Автоматический перенос данных и upgrade между установками с другим package ID не гарантируются. При внутреннем развёртывании можно использовать локальную или сетевую папку с полным набором `dist\1.2.4\releases`; пользователю Windows нужен доступ к ней.

Стандартный пакет включает CPU и Vulkan runtime, SQLite, WIC, WinRT OCR, PDFium и FFmpeg; CUDA не входит. Vulkan зависит от GPU и драйвера, CPU остаётся доступным вариантом. Фактическая совместимость и скорость зависят от устройства, драйвера, модели и размера индекса.
