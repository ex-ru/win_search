# Установка и распространение WAI для Windows

Здесь описаны установка WAI 1.2.0, состав штатного пакета и команды для сборки и публикации.

## Скачать готовый пакет

Репозиторий публичный. Откройте [релиз 1.2.0](https://github.com/ex-ru/win_search/releases/tag/v1.2.0) и скачайте установщик или portable-архив. Авторизация GitHub не нужна.

Релизные бинарные файлы не хранятся в Git: установщик и архив могут превышать лимит GitHub для одного файла, а в dist/releases они исключены из истории репозитория.

Скрипт download-release.ps1 скачивает пакет из этого публичного репозитория и проверяет SHA-256:

~~~powershell
.\scripts\download-release.ps1
~~~

Для переносимой версии:

~~~powershell
.\scripts\download-release.ps1 -Portable
~~~

Либо скачайте WinSearch.WAI-win-Setup.exe или WinSearch.WAI-win-Portable.zip со страницы [GitHub Releases](https://github.com/ex-ru/win_search/releases). Размер пакета зависит от сборки.

Стандартный пакет включает FFmpeg, PDFium, SQLite и CPU/Vulkan runtime. Модели в пакет не входят: приложение загружает выбранную модель при первом запуске и проверяет ее ожидаемый размер и SHA-256.

Новый пакет использует идентификатор WinSearch.WAI. Уже сохраненные данные WAI в %LocalAppData%\WAI остаются на месте. Автоматический перенос данных из других каталогов и автоматическое обновление установок с прежним идентификатором пакета не гарантируются. Установите новую версию, проверьте запуск и доступность нужных данных, прежде чем удалять прежнюю установку.

## Поддерживаемые пути вычислений

Релизный пакет содержит CPU и Vulkan backend. Использование Vulkan зависит от совместимого GPU и установленного драйвера; при проблемах можно выбрать CPU в настройках. CUDA в штатный пакет не входит.

Фактическая совместимость и скорость зависят от модели устройства, драйверов, выбранной модели и размера индекса. WAI не гарантирует одинаковое ускорение на всех видеокартах.

## Канал обновлений при развёртывании

По умолчанию приложение проверяет публичные релизы https://github.com/ex-ru/win_search через GithubSource без access token. Метаданные и контрольные суммы релиза 1.2.0 доступны анонимно; это не заменяет проверку реального обновления установленного приложения на целевой машине.

Для внутреннего развёртывания можно использовать локальную или сетевую папку: скопируйте в неё полный набор dist/releases и укажите путь в Advanced → источнике обновлений. Пользователь Windows должен иметь доступ к папке.

## Что ещё требуется перед широким распространением

В текущем пакете неполный набор лицензий сторонних компонентов и не сохранено точное происхождение части нативных бинарных файлов. Это отдельная незакрытая задача поставки, описанная в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Проверки приложения и контрольных сумм её не закрывают. Перед следующим общедоступным выпуском нужно подготовить соответствующие исходники/уведомления и проверить установку на чистой Windows; см. [проверку готовности](docs/PUBLICATION_REVIEW.md).

## Сборка полного пакета

Из корня репозитория запустите:

~~~powershell
.\port\WAI-5c5c1f3ae2b4346353e34704b4783956d1ae8c4f\windows\scripts\build-package.ps1 -Version 1.2.0
~~~

По умолчанию собирается полный пакет со встроенным FFmpeg. Скрипт размещает установщик, переносимый архив и контрольные суммы в dist\releases.

## Публикация релиза

После проверки сборки публикацию можно выполнить командой:

~~~powershell
.\scripts\publish-release.ps1 -Version 1.2.0 -NotesFile .\docs\RELEASE_1.2.0.md
~~~

Для REST API используйте переменную окружения GITHUB_TOKEN. Сначала отправьте проверенный коммит в GitHub. Скрипт использует SHA текущего коммита (или явно переданный TargetCommitish), создает черновик, загружает файлы из dist\releases и сверяет их размер и SHA-256 с ответом GitHub. Только после проверки всех артефактов релиз становится публичным. При ошибке загрузки черновик сохраняется для повторного запуска; опубликованный релиз скрипт не перезаписывает.
